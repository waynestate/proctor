Part 3 · The retake

The first sitting failed PROCTOR, not the apps

31 of the 82 apps are plain PHP with no composer.json. On the first run PROCTOR refused them with exit 2, "not a PHP project", which is no verdict at all for the apps that most need one.

First sitting and retake
SittingPROCTORFlaggedTool errors
First0.2.0, the day before its tag5131
Retake0.2.0 + "apps without composer.json get a verdict"811

The fix gives such an app a failing php-floor finding and runs every other check on its files. It shipped with a fixture test before the retake. The retake then found the one remaining error: on an app with a very large PHP tree, the parser ran past PHP's default 128 MB and the process died with exit 255. Raising PROCTOR's memory limit is queued with a test.

Part 4 · Sit it yourself

Run it on your own app

Install PROCTOR as a dev dependency and point it at CREED's policy.

Install

composer require waynestate/proctor --dev

Check, with the date pinned so the result repeats

vendor/bin/proctor check --path=. --format=json --policy=policy.json --today=2026-10-28

The proof harness ran exactly this inside php:8.4-cli on a throwaway copy of each app, with .git, auth.json and every .env removed first, and logged each app as one line (tool commit, unit id, command, exit code, duration, outcome) in the stack's internal record.

Part 5 · Rules of the exam

What this does not prove

  • PROCTOR reads the repository. It does not see what runs on a server, so an app whose host is newer than its composer.json says still fails php-floor.
  • The unpatched check needs --php-runtime, the PHP that serves the app; the run did not pass one, so that check stayed quiet.
  • The report's own version field still says 0.1.0 on the 0.2.0 tree. The marks are right; the label is queued for a fix.
  • Nothing reached a database, a sign-in service or any Wayne State server.
  • One tool error stands until the memory fix ships.
